# Міні-звіт з бізнес-аналізу

**Проєкт: переробка ВНС Львівської політехніки**

*Підготовлено для командного міту з бізнес-аналізу — чернетка для подальшого обʼєднання ідей*

## 1. Контекст і проблема

Віртуальне навчальне середовище (ВНС) Львівської політехніки побудоване на застарілій Moodle-подібній платформі. Інтерфейс перевантажений, навігація незручна (глибоко вкладені списки курсів, дрібний текст, відсутність сучасного UX), а функціональність обмежується виключно зберіганням файлів і форумами. Це особливо помітно на фоні того, що студенти щодня користуються значно зручнішими сервісами поза університетом.

Команда пропонує розробити навчальний (демонстраційний) бізнес-проєкт з переробки ВНС — не як реальне ІТ-рішення для впровадження, а як кейс для відпрацювання навичок бізнес-аналізу: визначення стейкхолдерів, формулювання вимог, побудову UML-діаграм (use case, activity, можливо class/sequence для ключових сценаріїв) та опис бізнес-цінності.

## 2. Мета проєкту

Показати, як має виглядати сучасне, зручне й «розумне» освітнє середовище університету з точки зору бізнесу: хто ним користується, які в них потреби, і які функції створюють найбільшу цінність за розумних витрат на розробку.

## 3. Стейкхолдери

| Стейкхолдер | Роль / інтерес у проєкті |
| --- | --- |
| Студенти | Основні користувачі: очікують зручний інтерфейс, швидкий доступ до матеріалів, допомогу з навчанням (конспекти, пояснення) |
| Викладачі | Завантажують матеріали, ставлять завдання, перевіряють роботи; зацікавлені в аналітиці успішності групи |
| Деканати / навчальний відділ | Контролюють успішність, потребують звітності та статистики по курсах і студентах |
| ІТ-відділ / Центр дистанційного навчання (ЦДН) | Адмініструють платформу, відповідають за стабільність, безпеку та інтеграції |
| Методичний відділ | Формує вимоги до структури курсів і навчальних матеріалів |
| Абітурієнти / нові студенти | Потребують простого й зрозумілого онбордингу під час першого входу |

## 4. Ключові проблеми поточної системи

- Застарілий, перевантажений інтерфейс — важко швидко знайти потрібний курс або матеріал
- Немає єдиного огляду дедлайнів і завдань з усіх предметів одразу
- Відсутність будь-яких «розумних» функцій — усе зведено до завантаження файлів
- Слабкий мобільний досвід
- Немає аналітики для викладачів (хто активний, хто відстає)

## 5. Пропоновані напрями розвитку

### 5.1 Оновлений інтерфейс і UX

Редизайн головної сторінки та кабінету студента: персональний дашборд замість плитки інститутів, зрозуміла структура курсів, адаптивність під мобільні пристрої, сучасна система пошуку по всій платформі (курси, файли, оголошення).

### 5.2 LLM-інтеграція: автоматичне конспектування

Студент або викладач завантажує презентацію / аудіозапис лекції / конспект — система автоматично формує стислий структурований конспект (тези, ключові терміни, визначення). Це базова ідея команди, яку варто розширити до повноцінного «AI-модуля» платформи (див. нижче).

### 5.3 Додаткові ідеї для обговорення на міті

- **AI-асистент по курсу:** чат-бот, що відповідає на запитання студента, спираючись лише на матеріали конкретного курсу (RAG на базі завантажених конспектів і презентацій викладача), а не на загальні знання з інтернету.
- **Єдиний календар дедлайнів:** усі дедлайни з усіх курсів в одному місці, з нагадуваннями.
- **Аналітика для викладача:** дашборд активності групи — хто не заходив у курс, хто не здав роботу, автоматичні нагадування таким студентам.
- **Доступність (accessibility):** підтримка озвучення тексту, збільшення шрифту, контрастні теми — важливий аргумент для розділу нефункціональних вимог.

## 6. Матеріал для UML-діаграм (актори та use case)

Нижче — попередній перелік акторів і сценаріїв використання, який команда може деталізувати у use case діаграмі та, за потреби, у діаграмі активності для сценарію «Отримання автоконспекту».

| Актор | Приклади use case |
| --- | --- |
| Студент | Увійти в систему; переглянути дедлайни; завантажити конспект лекції; отримати автоконспект від LLM; поставити запитання AI-асистенту; пройти тест для самоперевірки |
| Викладач | Завантажити матеріали курсу; переглянути аналітику активності групи; налаштувати автоматичні нагадування; перевірити роботи |
| Адміністратор ВНС | Керувати курсами й доступами; переглядати логи використання AI-функцій; модерувати контент |
| AI-асистент (система) | Обробити завантажений файл; згенерувати конспект/тест; відповісти на запитання студента за матеріалами курсу |

## 7. Очікувана бізнес-цінність

- Зменшення часу студента на пошук матеріалів і підготовку до занять
- Зниження навантаження на викладачів завдяки автоматизації рутинних питань (AI-асистент замість повторюваних відповідей у чатах)
- Вища залученість і менший відсоток студентів, що «губляться» через пропущені дедлайни
- Дані для деканатів про реальну активність студентів у курсах

## 8. Обмеження та ризики

- Вартість і складність інтеграції LLM (API, конфіденційність навчальних матеріалів)
- Опір змінам з боку викладачів, звиклих до поточної системи
- Потреба в модерації AI-відповідей, щоб уникнути помилкової інформації
