## DoR і DoD — коротко

- **DoR** — коли історію можна брати в спринт. Структура як у зразку (формат «As a … I want … so that …»,
  схвалення PO, макети, Gherkin-сценарії, відкриті питання, залежності, розмір на один спринт, декомпозиція).
  Додано три пункти під наш проєкт: обов'язковий негативний сценарій, для AI-історій — названа функція, яку може
  вимкнути викладач, і відомі ліміти AI-запитів, готові тестові дані (тестовий курс, викладач, студенти).
- **DoD** — коли історія готова. Перші пункти як у зразку (sub-tasks, code review, build, функціональний тест QA,
  UI як у макеті, баги закриті, приймання). Додано перевірки з нефункціональних вимог Частини 2 (доступ, швидкість,
  WCAG) і окремий пункт для AI-історій — бізнес-правило 1.
- У заповненому шаблоні біля кожного пункту DoR стоїть літера INVEST (`I`, `N`, `V`, `E`, `S`, `T`), бо шаблон вимагає,
  щоб чекліст відповідав INVEST.

## Примітки

- Документи згенеровано скриптом поверх оригінальних шаблонів: шрифти, заголовок і таблиця шаблону збережені.
- Назви елементів — ті самі, що на екрані 3 wireframe Частини 3 (вкладки «AI summary» і «Ask AI», «Key points», поле
  «Ask a question about this lecture» з кнопкою «Go», приклад питання «Why does BFS use a queue?»), а «Not found in the
  course materials» — дослівно з вимог Частини 2, щоб документи можна було звірити між собою.
