## Як кожна діаграма відповідає вимогам лаби

**ЛР 3, кооперація.**
- Лише об'єкти й зв'язки, які є в діаграмі класів: `:LecturePage`, `:AiAssistant`, `:Course`, `:AiSettings`, `:AiUsageRecord`, `:MaterialIndex`, `:ExternalLlmClient`, `ans : AiAnswer`, мультиоб'єкти `:SourceLink` і `:Slide`. Зв'язки, яких нема як асоціацій у класах, позначено `«local»`.
- Активні об'єкти (товста рамка): `Student` і `:AiAssistant`, бо запит виконується у фоні (NFR 2).
- Повідомлення за форматом лаби: `номер : повертане := ім'я(аргументи)`, умови в `[ ]`, ітерація `*[ ]`, стереотипи `«create»`, вкладена нумерація (`5.1`), виключення `5a`, `6a`, `8a`, `10a`.

**ЛР 4, послідовність.**
- Зовнішній агент найлівіший, об'єкти мають лінії життя, активації показані фокусами управління.
- Типи повідомлень за лабою: виклик (заповнений трикутник), асинхронне `ask()` (V-стрілка), повернення (пунктир), створення об'єктів (`ans`, `sourceLink`, `record` з'являються на лінії часу в момент створення), рефлексивні повідомлення (`checkAccess` та інші).
- Розгалуження показано кількома стрілками з однієї точки з умовами. Нумерація збігається з діаграмою кооперації.

**ЛР 5, стани.**
- Нотація: початковий і кінцеві стани, складений стан із послідовними підстанами, `entry`, `do`, перехід `подія [умова] / дія`, нетригерні переходи після `do`.
- Часові рамки: `after(30 s)` (відповідь LLM) і `at(00:00)` (кінець доби для лічильника).
- Конфліктів нема: умови з одного стану взаємовиключні (`[graded]` / `[not graded]`, `[requests + 1 < dailyLimit]` / `[requests + 1 = dailyLimit]`).

**ЛР 6, діяльність.**
- Лише нетригерні переходи, розгалуження з умовами в `[ ]`, злиття (merge), розділення й злиття паралельних потоків (fork / join), доріжки за об'єктами, прямокутники об'єктів (`slides : Slide`, `ans : AiAnswer`), кілька кінцевих станів.
- Паралельність справжня: повідомлення «answer is being prepared» виконується разом із перевірками (крок 7 UC-04), а показ відповіді й запис у лог виконуються паралельно (кроки 12–13).

**ЛР 7, компоненти.**
- Компоненти зі стереотипами лаби (`«executable»`, `«library»`, `«table»`), інтерфейси кружечками (імена з `I`), залежності пунктиром, розширений символ компонента з переліком реалізованих класів.
- Інтерфейси містять саме ті операції, які діаграма кооперації викликає повідомленнями `«call»`.

**ЛР 8, розгортання.**
- Вузли кубами зі стереотипами `«device»` і `«processor»`, фізичні з'єднання лініями без стрілок з протоколом, компоненти вкладено у вузли, Інтернет хмаркою (її лекція називає загальноприйнятою).
- Усі виконувані компоненти розміщені на вузлах (вимога лаби).

## Припущення (їх треба підтвердити в команді)

1. **30 с** на відповідь LLM (`after(30 s)`). У вимогах значення не задано, воно взято як розумне.
2. **Доступ до курсу й увімкнена AI-функція (BR-01) перевіряються ще раз у `ask()` на сервері**, хоча сторінка вже приховує поле (кроки 2–3 UC-04). Це стандартна практика безпеки; в діаграмах доступ перевіряє `checkAccess`.
3. **`ask()` асинхронний.** Сторінка залишається доступною й показує «answer is being prepared» (крок 7). Результат приходить через `showResult()` або `showMessage()`.
4. **Запис у лог (крок 13) відбувається після показу відповіді** (повідомлення 14), як у сценарії.
5. **Технології** взято з розділу 7.1 `Ідея_проекту.md` (React / Next.js, Node.js або Python, PostgreSQL з pgvector, зовнішній LLM API). Окрема черга й worker не показані, бо в діаграмі класів `AiAssistant` сам викликає `ILlmClient.generate`.
6. **Таблиці** `slide`, `ai_settings`, `ai_usage_record`, `ai_answer` лише для AI-функції. Решту таблиць платформи не показано.

## Що варто перевірити

- **PNG намальовані моїм власним скриптом за координатами з `.drawio`, а не самим draw.io.** Шрифт і стрілки трохи інші. Для фінального вигляду відкрийте кожен `.drawio` і зробіть File → Export as → PNG.
- Нумерація повідомлень у кооперації й послідовності має збігатися. Якщо змінюєте одну діаграму, змініть і другу (вимога лаби 3).
- Якщо змінюється `2. Class Diagram`, то імена операцій у повідомленнях треба узгодити з нею.
